# 递归与分治

## 什么时候会用到

问题能拆成**结构相同、规模更小**的子问题。分治是"拆开、各自解决、合并结果"，
递归是它的自然实现方式。

## 要点

### 写递归先写三件事

1. **终止条件**（base case）：规模小到什么程度直接返回？
2. **递归式**：规模 n 的问题怎么用规模更小的结果表示？
3. **归的时机**：是先递归再处理（后序），还是先处理再递归（前序）？

**终止条件漏掉或写错 = 栈溢出或死循环**，这是递归最常见的事故。

对应错因标签：`missing_case`。

### 汉诺塔：理解"整体搬运"

`hanoi(n, from, to, via)` 的递归式：

```
if (n == 1) { 直接把盘子从 from 移到 to; return; }
hanoi(n - 1, from, via, to);      // 把上面 n-1 个搬到中转柱
把最大的盘子从 from 移到 to;         // 这一步是"当前"的
hanoi(n - 1, via, to, from);      // 再把 n-1 个搬到目标柱
```

关键在于**把 n-1 个盘子当成一个整体**，不要试图在脑子里跟踪每一步。

移动次数是 `2ⁿ - 1`：`n = 1` 是 1 次，`n = 2` 是 3 次，`n = 3` 是 7 次。
**注意 n 稍大（如 30）时次数就会超过 int 范围**，需要 `long long`。

对应错因标签：`overflow`。

### 递归的代价：重复计算

朴素递归（如斐波那契、爬楼梯）会**指数级重复计算**同一个子问题。
`n = 40` 时就要跑几十秒，`n = 50` 基本跑不完。

判断方法：画一下递归树，看有没有同一个 `(参数组合)` 被算多次。
如果有，就必须加**记忆化**（把结果存起来）或改写成递推。

对应错因标签：`wrong_complexity`——逻辑对、但慢到超时。

### 递归深度与栈

递归层数等于问题规模（汉诺塔是 n 层）。`n` 很大时可能栈溢出。
多数题目的 n 不至于，但**用递归写线性扫描**（比如遍历 10⁶ 个元素）就会出事。

### 参数传什么很重要

汉诺塔要传三个柱子（源、目标、中转）。**忘了传中转柱、或在递归调用里把
三个柱子传错位置**，是最常见的错误——而且往往只有部分用例错。

## 常见错误

| 标签 | 表现 |
|---|---|
| `missing_case` | 终止条件漏写或写错，栈溢出 |
| `wrong_complexity` | 朴素递归重复计算，TLE |
| `overflow` | 递归结果（如 2ⁿ）超出 int 范围 |
| `uninitialized_state` | 记忆化数组忘了清零或初值不对 |

## 自检清单

- 终止条件是什么？`n = 1` 时能正确返回吗？
- 递归调用的参数顺序对吗？（源、目标、中转有没有传混）
- 画过递归树吗？有没有重复子问题？
- 结果的量级会溢出吗？该用 `long long` 吗？
- 递归深度会不会过大？
