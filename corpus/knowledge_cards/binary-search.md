# 二分查找与数值逼近

## 什么时候会用到

数据**有序**（或答案具有单调性）时，把线性扫描的 O(n) 降到 O(log n)。
第二种形态更常考：**在答案空间上二分**——比如求整数平方根，不是在数组里找，
而是在 `[0, x]` 这个范围内找满足条件的最大整数。

## 要点

### 二分的核心是不变量的维护

写二分不要靠记忆模板，靠想清楚**循环不变量**：

> 每一轮开始时，答案一定落在 `[lo, hi]` 这个闭区间内。

然后每一步都在缩小这个区间，并保证"答案仍在区间内"。

### 三种区间写法的区别

| 写法 | 初始 | 循环条件 | 收缩 |
|---|---|---|---|
| 闭区间 `[lo, hi]` | `hi = n-1` | `lo <= hi` | `lo = mid+1` / `hi = mid-1` |
| 左闭右开 `[lo, hi)` | `hi = n` | `lo < hi` | `lo = mid+1` / `hi = mid` |

**混用是最常见的 bug 来源**：初始用 `n`，循环条件却写 `lo <= hi`，
就会访问到下标 `n`（越界）。

对应错因标签：`off_by_one`。

### 中点计算要防溢出

`mid = (lo + hi) / 2` 在 `lo` 和 `hi` 都很大时会溢出（两者之和超过 int 上限）。
安全写法：`mid = lo + (hi - lo) / 2`。

### 单调性判断：二分的前提

二分要求"如果某个位置满足条件，那么它之后（或之前）的都满足"。
找不到这个单调性时，二分不适用——**不要硬套**。

对应错因标签：`wrong_complexity`——该用二分却线性扫描，导致 TLE。

### 整数平方根的边界

求 `floor(sqrt(x))` 时：

- `x = 0` 返回 0；`x = 1` 返回 1。
- 乘法 `mid * mid` 会溢出，改用除法判断 `mid <= x / mid`。
- 答案可能正好是 `x` 本身（当 `x = 1`），搜索区间上界要包含它。

对应错因标签：`boundary_condition`。

## 常见错误

| 标签 | 表现 |
|---|---|
| `off_by_one` | 区间开闭混用，死循环或越界 |
| `boundary_condition` | 0 / 1 / 最大值没处理；乘法溢出 |
| `wrong_complexity` | 该二分却线性扫描，TLE |

## 自检清单

- 我维护的不变量是什么？每轮结束时它还成立吗？
- 区间开闭写法前后一致吗？`hi` 初始值和循环条件匹配吗？
- 中点计算会溢出吗？
- 会不会死循环？（`lo` 和 `hi` 每轮都真的变小了吗？）
- `x = 0` 和 `x = 1` 这两个输入试过吗？
