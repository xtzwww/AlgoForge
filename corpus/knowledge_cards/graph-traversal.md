# 图的遍历：BFS、DFS 与连通块

## 什么时候会用到

数据之间存在"相连"关系时：网格里相邻的格子、朋友关系、道路网络。
两类典型问题——**能不能到达**（连通性）和**最少几步到达**（最短路）。

## 要点

### BFS 与 DFS 怎么选

| 需求 | 用哪个 | 原因 |
|---|---|---|
| 最少步数 / 最短路径（每步代价相同） | **BFS** | 按层扩展，第一次到达即最短 |
| 连通块计数、有没有路径、拓扑顺序 | DFS 或 BFS 都行 | 只关心可达性，不关心距离 |
| 网格中的最短路 | **BFS** | 边权都是 1 |

**用 DFS 求无权最短路是错的**——它会一路走到底，找到的路径不一定最短。
对应错因标签：`wrong_traversal`。

### 访问标记必须在"入队时"打，不能等到"出队时"

这是 BFS 最经典的坑。若在出队时才标记已访问，同一个节点可能被**重复入队**多次，
队列规模膨胀，轻则变慢，重则超时或内存超限。

```
queue.push(start);
visited[start] = true;          // 入队即标记
while (!queue.empty()) {
    u = queue.front(); queue.pop();
    for (v : neighbors(u))
        if (!visited[v]) { visited[v] = true; queue.push(v); }
}
```

对应错因标签：`uninitialized_state`——"标记没做对"在这里表现为超时而非错答案，
容易被误判成算法选错了。

### 网格题：边界检查与方向数组

在 `n × m` 网格上移动时，每一步都要确认**没走出边界**：

```
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};
for (int d = 0; d < 4; d++) {
    int nx = x + dx[d], ny = y + dy[d];
    if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;   // 越界就跳过
    ...
}
```

两个易错点：

- 条件写成 `nx > n` 而不是 `nx >= n`（差一位，越界访问）。
- 行列搞混（`n` 是行数还是列数），在方阵上测不出来，**非方阵才暴露**。

对应错因标签：`off_by_one`、`boundary_condition`。

### 连通块计数

对每个未访问的格子，做一次完整的 DFS/BFS，把能到达的都标记掉，
**每启动一次计数加一**。核心是"每个点只被访问一次"，因此总复杂度是 O(n·m)。

起点必须从 0 开始遍历整个网格——**漏掉第一行或第一列**是常见错误。

### 并查集：另一种连通性做法

维护 `parent` 数组，合并相连的两个点，最后统计不同的根有多少个。
路径压缩后接近 O(1)。

两个易错点：① **初始化时每个点的父节点是它自己**，忘了初始化会导致错误合并；
② 合并时要把两个根连起来，不是把节点直接连起来。

## 常见错误

| 标签 | 表现 |
|---|---|
| `wrong_traversal` | 该用 BFS 却用 DFS 求最短路 |
| `uninitialized_state` | 入队时没标记，节点重复入队导致超时 |
| `off_by_one` | 边界判断差一位；行列维度搞混 |
| `boundary_condition` | 起点即终点、网格只有一行/一列 |

## 自检清单

- 求最短路用的是 BFS 吗？
- 访问标记是在**入队时**打的吗？
- 边界条件四个方向都检查了吗？用的是 `>=` 还是 `>`？
- 网格非方阵时还对吗？（用 `2 × 5` 试一下）
- 起点就是终点、网格只有一行，这两种情况试过吗？
