# 枚举与暴力

## 什么时候会用到

当你**暂时想不到更好的算法**，但能确认"把所有候选试一遍"一定正确时。
枚举是最容易写对的方法，它的风险从来不是正确性，而是**规模**。

## 要点

### 先估规模，再决定能不能暴力

这是枚举题唯一的门槛。算法是"对每个候选检查一次"时，问自己：

> 候选有多少个？每个检查要多少步？两者相乘会不会超过约 10⁸？

- 10⁶ 以内：随便暴力。
- 10⁷ ~ 10⁸：能过，但要写得干净（避免循环里做重活）。
- 10⁹ 以上：必然超时，需要换算法或剪枝。

对应错因标签：`wrong_complexity`——**逻辑完全正确，只是太慢**。
这类错误的特征是 TLE 而不是 WA，别去查逻辑，先算复杂度。

### 枚举范围要覆盖全部答案

常见失误是枚举上界取小了。判断方法：**看数据范围**，而不是看样例。
样例里 `a` 是 5，不代表 `a` 最大是 5。

鸡兔同笼是典型：鸡的数量从 0 到总头数，**两个端点都要包含**。
写成 `i < heads` 会漏掉"全是兔子"这种情况。

对应错因标签：`off_by_one`、`missing_case`。

### 数位拆分：用取模与整除

水仙花数这类题需要拆出每一位数字：

```
while (x > 0) { digit = x % 10; x /= 10; }
```

注意两个坑：① 原数被改掉了，后面还要用的话先存一份；② `x = 0` 时循环不执行，
0 的位数是 0 还是 1？取决于题目定义。

## 常见错误

| 标签 | 表现 |
|---|---|
| `wrong_complexity` | 逻辑对但太慢，TLE |
| `missing_case` | 枚举范围漏掉某个端点 |
| `off_by_one` | 上界写成 `<` 而不是 `<=` |

## 自检清单

- 复杂度算过吗？最坏情况大约多少步？
- 枚举的上界取自**数据范围**还是样例？端点包含了吗？
- 拆数位时，原值还要用吗？有没有被破坏？
- 有没有可以提前退出的剪枝点？
