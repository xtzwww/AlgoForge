# 贪心策略

## 什么时候会用到

每一步都做"当前看起来最优"的选择，并且**不回退**。写起来比动态规划短得多，
但它有一个致命的适用前提——**局部最优能推出全局最优**。

## 要点

### 先证明，再写代码

这是贪心与 DP 最大的区别：DP 只要状态转移写对就一定对，贪心需要**论证**。

常用的论证方式：

- **交换论证**：假设存在最优解与贪心解不同，交换其中一对选择后不更差。
- **反例检验**：主动找一个贪心会失败的小输入。

**找不出反例 ≠ 贪心正确**。如果题目有 DP 的迹象（求方案数、有"选或不选"
的结构、约束互相牵制），优先考虑 DP。

对应错因标签：`wrong_algorithm`。

### 经典反例：硬币问题

面额 `{1, 3, 4}`，要凑 6：

- 贪心（每次拿最大的）：4 + 1 + 1 = **3 枚**。
- 最优：3 + 3 = **2 枚**。

贪心在这里就是错的。**只有当面额体系满足特定性质（如任意相邻面额成倍数）时，
贪心才成立**。题目若没给这个保证，就得用动态规划。

### 区间调度：按结束时间排序

这类题的贪心策略是：

1. 把所有区间按**结束时间升序**排序。
2. 依次扫描，能放就放（开始时间不早于上一个已选区间的结束时间）。

为什么按结束时间而不是开始时间：越早结束，留给后面的空间越多。
按开始时间排会得到反例。

对应错因标签：`inverted_condition`——排序键或比较方向选错。

### 相等与边界

- 区间首尾相接算不算重叠？取决于题意（`>=` 还是 `>`）。
- 空区间集合返回 0。
- 只有一个区间时返回 1。

对应错因标签：`missing_case`。

## 常见错误

| 标签 | 表现 |
|---|---|
| `wrong_algorithm` | 局部最优推不出全局最优，贪心不成立 |
| `inverted_condition` | 排序键或比较方向写反 |
| `missing_case` | 相接边界、空集合、单元素没处理 |

## 自检清单

- 我能说出为什么局部最优等于全局最优吗？说不出就换 DP。
- 主动构造过一个让贪心失败的小输入吗？
- 排序键是哪个？方向对吗？
- 空输入、单元素、首尾相接的区间试过吗？
