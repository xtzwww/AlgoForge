# 动态规划入门

## 什么时候会用到

问题可以拆成**重叠的子问题**，且每个子问题的最优解能组合出原问题的最优解。
典型的信号是：求"最多/最少/方案数"，且当前决策依赖之前的决策结果。

## 要点

### 三步走：状态、转移、边界

写 DP 之前先回答三个问题，**写下来**：

1. **状态**：`dp[i]` 表示什么？（要能用一句话说清，包含"前 i 个"这类范围限定）
2. **转移**：`dp[i]` 从哪些更小的状态推出来？怎么推？
3. **边界**：`dp[0]` 是多少？`dp[1]` 呢？

三个问题没答完就开始写代码，是 DP 出错的第一大原因。

### 状态定义决定了转移的难易

同一个问题可以有多种状态定义。例如最长上升子序列：

- `dp[i]` = 以第 i 个元素**结尾**的最长上升子序列长度 → 转移好写，答案取 max。
- `dp[i]` = 前 i 个元素的最长上升子序列长度 → 转移需要更多信息，容易写错。

选状态时问自己：**这个定义下，我能用更小的状态推出它吗？**

### 初始化必须显式做

DP 表**不会自动变成你想要的值**：

- 求最大值时，初值应设为负无穷（设 0 会让"不可达"被当成"值为 0"）。
- 求最小值时，初值应设为正无穷。
- 计数时，初值为 0，但 `dp[0] = 1`（空方案算一种）。

对应错因标签：`uninitialized_state`——典型表现是单看某一步对，
整体答案偏大或偏小。

### 递推与递归的取舍

爬楼梯这类问题是"斐波那契变体"，递推和记忆化递归都对。
但**朴素递归会指数级重复计算**，`n = 40` 就会慢到超时。
必须加记忆化（把算过的结果存下来）或改递推。

对应错因标签：`wrong_complexity`。

### 下标从 0 还是 1 开始

用 `dp[i]` 表示"前 i 个元素"时，通常从 `i = 1` 开始循环，
因为 `dp[0]` 是边界。此时遍历 `dp` 数组的下标与元素下标差 1，
**极易写错**。建议统一：要么全程 1-based，要么明确注释。

对应错因标签：`off_by_one`。

## 常见错误

| 标签 | 表现 |
|---|---|
| `uninitialized_state` | DP 表初值不对，答案系统性偏大/偏小 |
| `wrong_complexity` | 朴素递归指数级重复计算，TLE |
| `missing_case` | 边界状态（空集、单元素）没单独处理 |
| `off_by_one` | 状态下标与元素下标错位 |

## 自检清单

- 用一句话说出 `dp[i]` 的含义了吗？
- 转移方程覆盖了所有情况吗？有没有"不选"的分支？
- 初值设置与"求最大/最小/计数"匹配吗？
- 空输入、只有 1 个元素时，`dp[0]` 和 `dp[1]` 对吗？
- 时间复杂度是多少？会不会重复计算？
