# 循环与条件控制

## 什么时候会用到

几乎所有题。这里的问题是**错误最隐蔽**的一类：循环边界差一位、条件漏一种情况，
在样例上照样跑对，只有特定输入才崩。

## 要点

### 循环边界：想清楚"包不包含"

写 `for (int i = 0; i < n; i++)` 还是 `i <= n`，取决于你要处理几个元素。
判断方法不是背，而是**代入最小规模手算**：

- `n = 0` 时循环体执行几次？应该是 0 次吗？
- `n = 1` 时呢？
- 最后那次迭代访问的下标是 `n-1` 还是 `n`？后者越界。

对应错因标签：`off_by_one`。

### 边界值不是"特殊情况"，是逻辑的一部分

有些题的正确性完全建立在边界处理上：

- 求最大公约数时，其中一数为 0 怎么办？
- 累加求和时，结果会不会是 0？初始值设 0 还是 -1？
- 判断素数时，0 和 1 都不是素数，但循环从 2 开始时它们根本进不去循环——
  于是被误判成素数。

对应错因标签：`boundary_condition`。

### 条件分支要"穷尽且互斥"

三个数排序这类题，最容易漏掉一种大小关系，或者让两个分支同时命中。
写之前先把所有情况列出来（3 个数有 6 种排列），确认每个都落进某个分支。

对应错因标签：`missing_case`。

## 常见错误

| 标签 | 表现 |
|---|---|
| `off_by_one` | 循环多跑或少跑一次，下标越界或漏算最后一个 |
| `boundary_condition` | 边界值（0、1、负数）让本来正确的逻辑失效 |
| `inverted_condition` | 条件方向写反 |
| `missing_case` | 某个必需的分支根本没写 |

## 自检清单

- 循环边界用 `n = 0` 和 `n = 1` 手算过了吗？
- 数组访问的最大下标是多少？会不会等于长度？
- 素数/约数/区间类题目，端点值（0、1、区间两端）单独试过吗？
- 所有分支加起来能覆盖全部输入情况吗？
