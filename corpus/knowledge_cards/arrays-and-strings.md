# 数组与字符串处理

## 什么时候会用到

需要按下标访问、统计、比较或原地修改一串数据时。数组题的错误集中在
**下标**，字符串题还多一层**编码与结尾**。

## 要点

### 下标从 0 开始，最大合法下标是 n-1

反向遍历最容易写错：从 `n-1` 开始，到 `0` 结束（**包含 0**）。
写成 `i > 0` 会漏掉第一个元素。

对应错因标签：`off_by_one`。

### 计数数组必须先清零

统计字符出现次数时，如果计数数组是全局的、或跨测试用例复用的，
**上一轮的数据会残留**，导致答案虚高。局部变量在多数语言里会初始化，
但静态/全局数组不会。

对应错因标签：`uninitialized_state`——表现很典型：单测一个用例对，
连着跑多个用例就错。

### 双指针：两端向中间收敛

回文判断是标准形态：`i` 从 0 往右，`j` 从末尾往左，相遇即结束。

```
i = 0; j = n - 1;
while (i < j) { if (s[i] != s[j]) return false; i++; j--; }
```

两个易错点：① 循环条件写成 `i <= j` 时，奇数长度串会多比一次（多数情况无害，
但涉及交换或修改时会出错）；② 空串和单字符串要能正确判为回文。

对应错因标签：`boundary_condition`。

### 遍历方向要符合题意

"逆序输出"要求从后往前读，写成从前往后输出就是错的——**逻辑没错，方向错了**。

对应错因标签：`wrong_traversal`。

### 字符串的"结尾"

- C 风格字符数组以 `\0` 结尾，长度要**多留一位**。
- 读入可能带空格时，`cin >> s` 会在空白处停下，需要 `getline`。
- 行尾的换行符可能被读进字符串里，比较前要先去掉。

## 常见错误

| 标签 | 表现 |
|---|---|
| `off_by_one` | 反向遍历漏掉首元素、下标越界 |
| `uninitialized_state` | 计数数组跨用例残留 |
| `wrong_traversal` | 遍历方向与题意相反 |
| `boundary_condition` | 空串、单字符、全相同字符没处理 |

## 自检清单

- 数组开得够大吗？最大下标是多少？
- 反向遍历时，`0` 这个下标被包含了吗？
- 计数/标记数组在每轮开始前清空了吗？
- 空输入、长度为 1、全相同字符，这三种情况试过吗？
