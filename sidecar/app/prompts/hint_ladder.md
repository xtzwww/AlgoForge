## 三级提示的写法

三级必须**由浅入深**：学生读到第几级，就该能往下走一步。

1. `level: 1` —— **只给方向**。说出该去检查哪一类东西（例如「乘法之前的
   中间结果」「循环的终止条件」），**不要**出现行号、变量名或具体表达式。
2. `level: 2` —— **指出位置**。点名具体的行或表达式（例如「第 4 行的
   `a * b`」），但**不要**说出该怎么改。
3. `level: 3` —— **给出关键判据**。写出学生自己动手就能验证的那一步
   （例如「把 `a * b` 的两个操作数都转成 64 位再相乘，看结果是否变化」），
   仍然**不要**整段贴出改好的代码。

三级之间必须说不同的话。把同一句话换个说法不算下一级——那说明这一级没有
给出新的信息。

另外给一份 2-4 条的 `self_check` 自检清单：学生改完之后逐条自查的问题，
每条都要能独立回答「是 / 否」，例如「输入里两个乘数都是 10^9 时，结果还是
对的吗」。

## 输出格式

只输出一个 JSON 对象，不要包裹在 markdown 代码块里，不要有任何前后说明文字：

{
  "levels": [
    {"level": 1, "text": "<中文，只指方向>"},
    {"level": 2, "text": "<中文，指出位置>"},
    {"level": 3, "text": "<中文，给出可验证的判据>"}
  ],
  "self_check": ["<中文，一条能用是/否回答的自查问题>", "<中文，另一条>"]
}

约束：
- `levels` 必须**正好 3 项**，`level` 依次是 1、2、3，不要从 0 开始。
- 三级提示的文字必须互不相同，也不能把同一句话换个说法。
- 字符串里不要出现真实的换行，需要换行就写 `\n` 这两个字符。
- 最后一个字段后面不要加逗号——JSON 不允许尾逗号。
- 不要输出 `levels` 与 `self_check` 以外的任何字段。
- 不要在这里重复错因分析，也不要写出正确代码——学生要自己走到那一步。
